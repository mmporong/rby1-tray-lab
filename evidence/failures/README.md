# 대표 실패 영상 두 개

탐색 중 관찰한 실패를 두 개만 골랐다. 성공률 표본이나 최종 코드의 성능 비교용 데이터는 아니다. 실제 MuJoCo 물리 실행을 촬영했으며 성공 장면으로 편집하지 않았다.

| 영상 | 관찰된 결과 | 기록 범위 |
|---|---|---|
| [01 · 상승 초반 접촉 이탈](01-early-lift-contact-loss.mp4) | 파지와 초기 상승 뒤 52.826 s에 `release_before_seat` | 경로 연속성을 보강하던 중의 실행. 초기 폐쇄 기준을 바꾼 조건이지만 그 값 하나를 원인으로 단정하지 않는다. |
| [02 · 높은 위치에서 안전 정지](02-late-lift-safety-stop.mp4) | 70.812 s, 트레이 중심 약 1.25 m에서 한 pad 이탈로 정지 | 수정 전 인터랙티브 백엔드의 실제 실행. 영상은 엄격 평가기의 정지를 보존한다. |

두 번째 사례는 별도 진단 실행에서 실패 판정을 유지한 채 물리를 이어 계산했다. 최초 접촉 소실은 2 ms 뒤 회복됐지만, 71.309 s에 시작한 2.384 rad 관절 경로 점프 뒤 접촉이 무너졌다. 명령 속도는 약 15.2 rad/s까지 치솟았고 트레이가 옆으로 튀었다. 진단 원시 수치는 `02-post-failure-diagnostic.json.gz`에 있다. 이 진단을 성공 실행으로 분류하지 않는다.

첫 영상은 실행 당시 소스 해시를 기록했지만 미커밋 탐색 코드였다. 두 번째 영상의 예전 뷰어는 로드된 소스 해시·전체 설정을 내보내지 않았다. `02-related-diagnostic-config.json`은 관련 진단 설정이며 뷰어에서 추출한 설정으로 가장하지 않는다. 따라서 이 두 영상은 실패를 설명하는 기록으로 쓰고, 재현성·최종 성능 수치는 커밋 기반 CLI 산출물에서 판단한다.

영상 SHA-256·조건·버전 한계는 `index.json`에 보존한다. 과거 소스 해시를 현재 커밋의 해시로 바꾸지 않는다.
